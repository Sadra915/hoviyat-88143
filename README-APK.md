# ساخت APK از هویت — دو اپ جدا (اصلی + پنل ادمین)

## قبل از شروع — چیزی که باید بدونی

من نمی‌تونم از همین‌جا (sandbox من) یه فایل APK واقعی بسازم — نه Android SDK دارم،
نه Gradle، نه دسترسی شبکه برای نصب ابزارها. چیزی که آماده کردم، **پروژه و تنظیمات**
هست؛ خود ساختن APK باید روی یک کامپیوتر واقعی (یا یک سرویس CI رایگان) انجام بشه.

**نکته‌ی مهم درباره‌ی Termux:** اگه داری از گوشی/Termux کار می‌کنی، ساختن APK با
Gradle معمولاً روی Termux قابل‌اعتماد نیست (نه SDK کامل اندروید داره، نه منابع کافی).
دو راه واقعی داری:
1. یه کامپیوتر (ویندوز/مک/لینوکس) با Android Studio نصب‌شده.
2. GitHub Actions (رایگان) — یه workflow می‌سازی که خودش APK رو در ابر می‌سازه و به‌عنوان
   artifact بهت می‌ده، بدون این‌که خودت Android Studio نصب کنی. اگه بخوای، یه
   `.github/workflows/build-apk.yml` هم برات می‌سازم.

## چرا دو تا اپ جدا؟

پنل ادمین (`admin.html`) از اول یه entry point کاملاً جدا با کد جدا (`admin-app.js`) بوده.
به‌جای قاطی کردنش با اپ اصلی، هرکدوم یه اپ اندرویدِ جدا می‌شن:

| | اپ اصلی | پنل ادمین |
|---|---|---|
| appId | `ir.hoviyat.app` | `ir.hoviyat.admin` |
| اسم روی گوشی | هویت | هویت ادمین |
| صفحه‌ی ورودی | `index.html` | `admin.html` |

چون `appId` دوتاشون فرق داره، اندروید هردو رو به‌عنوان دو اپ کاملاً جدا می‌بینه —
می‌تونی همزمان هردو رو نصب کنی، هرکدوم آیکون/اسم خودشو داره.

## مراحل (روی کامپیوتر با Android Studio نصب‌شده)

### ۱) پیش‌نیازها
- Node.js (نسخه ۱۸ به بالا)
- Android Studio (شامل Android SDK)
- JDK 17 (معمولاً همراه Android Studio نصب می‌شه)

### ۲) نصب ابزارها
```bash
cd hoviyat-88143-main      # پوشه‌ی پروژه
npm install
```

### ۳) ساخت اپ اصلی
```bash
npm run app:add-android     # فقط بار اول — پروژه‌ی اندروید رو می‌سازه
npm run app:open            # Android Studio رو با پروژه باز می‌کنه
```
تو Android Studio: **Build → Generate Signed Bundle / APK** → APK رو انتخاب کن →
یه keystore جدید بساز (یا اگه از قبل داری، همونو استفاده کن) → Build.

### ۴) ساخت اپ ادمین (کاملاً مستقل)
```bash
npm run admin:add-android
npm run admin:open
```
همون مراحل Build → Generate Signed APK رو برای این پروژه‌ی جدا هم تکرار کن.

### هروقت کد را تغییر دادی
دیگه لازم نیست `add-android` رو دوباره بزنی (فقط بار اول لازمه). برای هر تغییر بعدی:
```bash
npm run app:sync      # برای اپ اصلی
npm run admin:sync    # برای اپ ادمین
```
بعد دوباره از Android Studio Build بگیر.

## آیکون و اسم اپ

`build-dist.mjs` یه `manifest.json` جدا برای هرکدوم می‌سازه (برای نصب PWA/مرورگر)، ولی
**آیکون واقعی APK** رو باید با ابزار رسمی Capacitor بسازی (چون اندروید به فرمت/سایزهای
خاص خودش نیاز داره، نه فقط یه PNG ساده):
```bash
npm install @capacitor/assets --save-dev
npx capacitor-assets generate --android --iconBackgroundColor '#F0651E'
```
این کار رو برای هر دو پروژه (بعد از `add-android` هرکدوم) جدا انجام بده تا آیکون‌های
درست تو `android/app/src/main/res/` هرکدوم قرار بگیره.

## نکته‌ی امنیتی

پنل ادمین از همون Supabase backend استفاده می‌کنه و دسترسی ادمین همچنان سمت سرور
(`is_admin()`) چک می‌شه — یعنی حتی اگه یکی فایل APK پنل ادمین رو گیر بیاره و نصب کنه،
بدون حساب ادمین واقعی هیچ‌کاری نمی‌تونه بکنه. جدا بودن اپ فقط برای تجربه‌ی کاربری
تمیزتره، نه یک لایه‌ی امنیتی اضافه — لایه‌ی امنیتی واقعی همون RLS/`is_admin()` سمت
دیتابیسه که از قبل هست.
